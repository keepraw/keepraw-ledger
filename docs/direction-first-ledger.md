# 借贷方向优先

账本以银行的金额列、符号约定、借贷标记和账户分区识别方向：借记为正，贷记为负。商户描述中的还款、退款、返现、优惠等文字不能改变方向；无法判断业务性质可以正常入账。银行原始描述和用户分类继续保留。

## 财务与复核

- 总览展示借记总额、贷记总额（绝对值）、净额和有效入账笔数。净额为借记减贷记。借记可能含费用、利息、取现，不能称为实际消费。
- 汇总、月度趋势、银行/卡片分布都按方向计算。总览继续只统计人民币结算记录；其他币种不混加，也不换汇。已排除记录、未实际入账的分期原始记录、仍有方向冲突的记录不进入有效金额统计。疑似重复仍提示复核，不自动删除。
- `transaction_type_unclear` 不再是有效复核原因；`typeUncertain` 已移除。真实金额/方向矛盾仍触发 `amount_direction_unclear`。金额格式、币种和精度无法安全解析时仍拒绝导入。金额符号与银行方向冲突时保留原始金额和原文，保存交易并进入复核，不因符号冲突拒绝整份账单。
- 两套对账都不依赖 `type`。余额等式保留，明细借记与银行新增支出、费用、利息的合计核对，明细贷记与银行贷记汇总核对。有借贷分项时，净额恰好抵消也不能掩盖分项错误。没有可靠逐笔费用/利息依据时跳过细分检查，但费用/利息仍包含在借记总额和余额等式中。

## 保留的 type 字段

`Transaction.type`、`ParsedTransaction.type`、`NormalizedLegacyRow.type`、指纹输入的 `type` 和原生 XLSX 的历史类型列继续存在。`TransactionType` 和中文标签表是冻结的兼容词表。`legacyTypeForIdentity()` 只复现旧编码，以保持文件重导入时的指纹、交易 ID 和 occurrence 对应关系。其旧兜底编码仍可能为 `purchase` 或 `payment`，不表示识别出了消费或还款；不能用于方向、分类、业务性质复核、财务统计或账单总额。未知贷记不会因此分类为还款/退款。

疑似重复的宽松候选按银行、卡、日期、结算币种、方向和金额寻找，不使用历史类型；精确身份验证仍保留旧字段。跨来源身份无法安全合并时仍按疑似重复复核，不把业务类型不明确本身当成问题。

交易页与复核页展示方向，原类型筛选改为方向筛选。CSV 和原生 XLSX 将兼容列明确命名为「历史类型（仅身份兼容）」。人类可读账本归档的首页移除类型列，原值放在 `Technical Metadata.legacy_type_identity_only` 中。原生 XLSX 导入仍严格核验历史类型与指纹的一致性，不重新生成身份。

## 分期原始记录的独立排除依据

新增 `postingExclusion`，财务代码只检查此依据，不根据类型排除记录：

- `bocom_plan`：交通银行原始行与银行计划表的产品、总额匹配，保存计划表原文、表/行位置和解析值。
- `bank_original_marker`：支持的账单格式明确区分原始本金与每期入账的源标记，保留源标记和原文。贷记不会因原始本金标记被排除。
- `legacy_installment_exclusion`：旧版本已排除的原始记录。旧数据没有独立保存完整计划证据，迁移只保留旧排除决定并明确标记这个限制，不声称补回了银行证明。

新记录明确保存 `null` 表示没有排除依据。旧格式边界中字段缺失且旧版已经排除的记录，一次转换为兼容排除依据；之后改变历史 `type` 不改变财务结果。原生 XLSX 继续接受冻结的 20/21/22/23 列格式，新导出为 26 列，附带「入账排除依据」「方向复核标记」「银行方向依据」「人工方向决定」和「完整复核标记」。旧格式与新格式均保留原始 ID、指纹和重复识别；已有记录的排除效果冲突时拒绝覆盖，重复导入不会覆盖更完整的现有来源证据。

## v6 升级与旧备份

v5 原迁移不变。v6 在 Dexie 的单个 versionchange 事务中清除旧类型标记：

1. 检查原币金额、结算金额和方向，真实符号冲突转换为 `amount_direction_unclear`；零金额不凭符号判定冲突。
2. 发现真实金额符号/方向冲突时，原状态为 ok 或 pending 的记录统一进入 pending；confirmed/rejected 原样保留。没有方向冲突时，pending 且清理后没有其他复核原因才恢复 ok，其他标记完整保留。
3. 将旧分期排除决定保存为独立兼容元数据。

不重写金额、币种、日期、方向、描述、分类、ID、指纹、occurrence 或来源字段，不重导入、不删除交易，不改账单、附件、设置或备注。升级失败时数据和版本一起回滚，重复执行无额外变化。

JSON V1/V2 和 ZIP 共用不可变的恢复规范化函数；只在兼容输入边界接受旧类型标记，落库前清理。保留原有原子事务、冲突拒绝、备注与附件回滚以及重复恢复行为。V1/V2 的格式标识、版本号和 ZIP 布局不变。

## 验证

所有新增数据均为合成数据。`tests/directionFirst.test.ts` 覆盖六家银行、三种历史适配器、类型元数据不影响财务、方向冲突、借贷分项错误相互抵消、v5→v6、升级失败重试、JSON V1/V2、ZIP、分期与原生 XLSX 身份。`e2e/directionFirst.spec.ts` 在真实 Chromium IndexedDB 中验证升级回滚、重开、旧备份和方向筛选。这两组测试已加入 `npm run test:migration`。

## 符号冲突的原始证据

建行、中信的有符号金额列按原始符号读取，方向来自结算金额列；交行的账户分区、中行的金额列、工行的借贷标记提供方向。允许在正常的贷记分区将同号的正数金额幅度规范为负数，但必须先检查两金额符号是否矛盾或负数是否落在借记分区。发生冲突时两金额都保留源值，不调用方向规范化覆盖证据，并设置 `amountDirectionUnclear`，由 ingest 生成方向复核标记。

中行同时出现借记与贷记列时，两列都独立进行严格金额解析；一列精度无效不能被另一列覆盖。两列都有效则无论正负和 PDF 文本顺序都进入方向复核，明确选用借记列保存金额，完整双列原文保留在 `rawText` 与原始附件中。未解决的冲突不计入有效财务统计，也不能通过对账。

原生 XLSX 同样保留这类冲突金额和明确的方向字段，新导出的第 23 列独立保存 `amount_direction_unclear`；中行双列等结构矛盾即使单个金额符号正常也不会丢失方向复核。恢复时合并金额检查和该显式标记，避免可保存的银行记录在往返恢复时被丢弃。金额格式、精度、方向枚举和指纹/ID 校验仍严格执行；同一已有 ID 下方向或其他金融字段不一致仍阻止恢复，不覆盖本机记录。JSON/ZIP 格式不变。


## ABC 金额约定与人工方向闭环

农行分区优先；没有有效分区时，按银行明确的入账金额约定「支出为负、贷记为正」确定方向。原币列允许金额幅度，负的原币借记属于异常；不能把正常借记的「原币正、入账负」误判为两列冲突。统一 `resolveBankAmounts(..., 'abc')` 在规范化之前检查两列符号：出现异常时，两列原值与 `rawText` 均保存，正常交易的历史身份不变，格式、币种和超精度错误仍拒绝整份导入。

每个银行解析器独立保存 `directionEvidence`：`bank` 表示金额列、标记或分区提供了可靠方向；`missing` 表示没有可靠方向或银行结构字段互相矛盾。工行无有效标记的正数、以及中行同一行双金额列属于后者。旧记录未保存独立方向依据的异常也要求用户明确选择，不从历史类型或普通 confirmed 状态补证据。

复核分两种操作：可靠方向的符号矛盾明确「接受银行借记/贷记方向」；缺失/矛盾的依据必须在无默认值的选择框中选择借记或贷记。普通单笔和批量确认都不能代替方向决定。`directionResolution` 独立保存接受方式和最终方向；解决方向仅移除方向标记，疑似重复、低置信度等其他标记完整保留并继续按原流程处理。

`effectiveAmountForDirection()` 是财务金额唯一入口：未解决方向问题返回 null，不进入可信统计；正常记录使用原金额；已明确解决的记录按最终方向取原金额的正/负绝对值。原币与入账金额分别计算，汇总、趋势、分布和两套对账使用同一规则。人工方向决定触发同一个数据库事务内的账单派生状态重算，不新建交易，不改变原始金额、存储方向、ID、fingerprint 或 occurrence；多次确认仍只计入一次。交易页方向筛选使用最终方向，显示有效金额并附原始金额。

新原生 XLSX 保留原有 23 列，追加第 24 列银行依据、第 25 列人工方向决定（包含最终方向）、第 26 列完整复核标记。旧第 11 列仍是存储方向，原金额列仍保留原符号，不能为了身份校验而规范化冲突金额。继续接受完整旧 20/21/22/23 列；旧格式没有人工决定的方向问题仍需显式处理。新格式恢复已解决的记录后不重新要求方向复核，未解决的记录继续复核，其他标记不丢失。`reviewFlagsSource: native_export` 区分新版显式导出的标记，避免旧版虚假低置信度修复误删真实标记。JSON V1/V2 与 ZIP 原格式继续承载这些可选元数据；同一已有 ID 的金融字段或人工方向决定冲突时原子拒绝，不覆盖现有记录。人类可读归档展示有效金额与最终方向，Technical Metadata 保存原始金额、方向、依据、决定和原文。

新增 `tests/directionResolution.test.ts` 与 `e2e/directionResolution.spec.ts`，均纳入 migration 验收，覆盖 ABC 两列原符号、A/B 两种人工流程、借/贷记有效金额、两套对账、其他标记保留、不可普通确认、无重复计入、type 元数据无关、原生旧新格式和 JSON/ZIP 往返。
