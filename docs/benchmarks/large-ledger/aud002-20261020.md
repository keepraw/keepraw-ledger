## Implementation and scope

The final production change is confined to `TransactionsPage.tsx`. For at least
256 rows and at most N/4 distinct text values, it collates the distinct values
once, groups the original transaction references, and stably sorts each group
by the existing ascending transaction-date tie-break. It then concatenates the
complete groups before the existing pagination/export path. Collation work is
O(U log U), where U is the number of distinct descriptions/types, instead of
O(N log N). Group date sorting still costs O(sum(n_i log n_i)); full-history
filter/search, pagination, and synchronous main-thread execution remain.

Small or mostly-unique lists retain the original direct comparator. Different
strings with equal collation order also fall back to that comparator: grouping
those strings separately would incorrectly reorder their stable interleaving.
Null text remains last in both directions. The tests cover both fallback paths,
Unicode equivalence, null dates/text, exact date ties, both directions, type
grouping, numeric money/currency ordering, composed filters, search fields and
pagination. Input rows are neither mutated nor replaced.

The first rank-map prototype is retained as
`aud002-20261020-rank-experiment.json`: description core improved from 194.5 to
132.8 ms at 100k, but missed the predeclared 120 ms budget; edit commit/paint also
missed their budgets. It is not the accepted final result. The final grouping
path removes per-comparison rank-map lookup and leaves date/money comparisons
unchanged. There is no worker, store/subscription change, database/schema edit,
new dependency or Golden change. AUD-004/005/001/014 persistence safeguards remain
on their existing paths. AUD-006 and AUD-003 are outside this PR.

`analytics.ts`, `repository.ts`, and `AppStore.tsx` were inspected. The baseline
shows the existing edit path already does zero full transaction reads. Snapshot
reads/object materialization (~573 ms at 100k) dominate startup and refresh;
full searches (~31 ms), date sorting (~107 ms), full JSON backup reads/encoding
(~1380 ms) and React commit/paint are separate costs. The patch targets the
measured repeated-description comparison cost rather than rewriting unrelated
storage/backup/state ownership. It does not promise sub-frame 100k interactions,
mobile/low-memory support or acceleration of high-cardinality text.

**Budget result: 25/26 pass.** Description computation improves 60.7% at 18k and
54.2% at 100k; description UI improves 33.7%/46.7%. All 100k budgets pass. The
18k refresh-paint median of 184.5 ms misses 180 ms by 4.5 ms (2.5%), and is 38.9%
slower than baseline. The budget checker correctly exits 1; it is not reported
as passing and the budget was not relaxed.

The unchanged snapshot path is slower in this campaign too: 18k read median
109.6→136.3 ms, refresh resolution/commit 124.2/124.0→177.7/177.5 ms. The refresh
miss is concentrated before paint, while isolated date sorting and actual sort
clicks improve. These observations suggest read/materialization and allocation/
GC/scheduling variability contribute, but this campaign does not isolate the
cause or rule out allocation pressure from the new grouping path. The observed
regression remains a review risk. A single host and five samples do not support
claiming a statistically reliable IO, search, startup or backup improvement.

At 100k, edit API resolution is 1.8→1.6 ms, state commit 119.3→114.7 ms and
paint 119.9→115.2 ms, with **zero full transaction reads for every edit sample**.
Commit/paint includes derived list computation, React rendering and DOM work;
this harness does not separately profile each React component or compositor.

## Remaining limits and review risks

- 18k refresh paint misses its declared budget; backup encode variability and
  full snapshot IO/materialization remain unresolved. Review allocation pressure
  and measure on the intended device before treating these as release SLAs.
- All calculations still run on the main thread; filters/search remain O(N),
  full snapshots remain O(N), and mostly-unique/equivalent text retains the
  original full sort. No claim is made that all of AUD-002's scaling limits vanish.
- Grouping adds O(N + U) temporary references. Memory peaks, mobile and low-memory
  devices were not measured; no worker or indexed-query architecture was justified
  by this narrow repeated-text experiment.
- Human review should focus on stable Unicode-equivalent fallback, null-last/date
  ties, full-list export/pagination and preservation of AUD-007 currency/numeric
  behavior. Regression tests cover these boundaries. Do not merge automatically.
